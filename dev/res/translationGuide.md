# 翻訳ルール（正本）

Pathfinder: Wrath of the Righteous 日本語化の訳文スタイルガイド。
`CLAUDE.md` からはここへのリンクのみを置く（このファイルが更新の実体）。

世界観：TRPG / D&D / 神話 / デーモン / 十字軍 / 中世。

## スタイル

- 自然で流暢な日本語。助詞（が・を・に）を正しく。
- **固有名詞・人名に漢字を当てない。** カタカナ音写に統一（`Konomi` → `コノミ`、× `木ノ美`）。
- 種族名もカタカナ（`mongrel` → `モングレル`、× `雑種`）。
- ナレーション・説明文は中立な地の文／システムメッセージとして訳す。
- 話者の口調は `dev/res/speakerProfiles.json` に厳密に従う（一人称・二人称・敬語レベル）。
- 話者不明のときは前後の文脈から推測。それでも不明なら**丁寧語（です・ます）**。
  勝手に乱暴・高圧的な男性口調（「お前は〜だ」「〜なのだ」）にしない。
- 用語は `dev/res/glossary.json` の `target` を優先。
- **読点（、）を多用しない。** 訳しているのはナレーションではなく会話（セリフ）である。
  基準は「読みやすさ（誤読しないか）」ではなく「話し言葉としての自然さ・流暢さ」——
  実際に声に出したときにその位置で本当に息継ぎ・間を置くか、で判断する。
  - **1文につき読点は基本1個まで。** 逆接（が/けれど）や条件節（ば/たら）など許容パターンに
    当てはまる読点でも、その文にすでに読点が1つあるなら原則として残りは削る
    （例: 「ですが、あなたが〜戦っている限り、私はお力添えいたします。」→
    「ですが、あなたが〜戦っている限り私はお力添えいたします。」）。
  - 短い文（せいぜい20〜30字程度まで）に読点を打つのは、軍隊口調のような区切り・命令調の
    キャラクター性を出したいときか、特定の語を強調したいときだけに限る。それ以外の短文は
    読点なしで言い切る。
  - 三つ以上の並列列挙は読点を使ってよい（列挙は「間」ではなく区切りとして自然）。
  - 「〜は、」「もちろん、」「ですから、」のような軽い前置き・副詞の直後の読点は基本的に不要
    （切っても誤読の心配がない場合は削る）。
  単文を接続助詞で安易につなげて読点を増やすより、文を分けるか言い切る方を優先する。
- **代名詞・主語・指示語は文脈で分かるなら省略する／訳しすぎない。** 英語は主語や指示語を律儀に
  繰り返す言語だが、日本語は省略するほうが自然。以下のパターンに注意する。
  - 原文の `he`/`she`/`they`/`him` などを逐語的に「彼は」「彼女を」と訳出しない。直前の地の文
    （`彼は鋭い眼差しをあなたに向ける` 等）や話者情報から主語が明らかな場合は省略する
    （例: `He must have thought you were suspicious of him.` →
    ×「あなたに勘づかれていると彼は思っていたに違いない」
    ○「あなたに勘づかれていると思っていたに違いない」）。
  - 1文の中で同じ語（特に「あなた」）が2回出てくる場合、2回目以降は文脈で明らかなら省略する
    （例: `The moment you let them into the city, he'll order them to seize you.` →
    ×「あなたが彼らを街へ招き入れた瞬間、あなたを捕らえるよう命じるでしょう」
    ○「彼らを街へ招き入れた瞬間、あなたを捕らえるよう命じるでしょう」）。
  - `That, that...` のような強調のための指示語の繰り返しも、日本語でそのまま2回訳すと不自然に
    なりやすい（例: `That traitor, that... blockheaded fool!` →
    ×「あの裏切り者、あの……救いようのない愚か者め！」
    ○「あの裏切り者、……救いようのない愚か者め！」）。
- タブ・改行は原文と同数を保つ。
- 出力は訳文のみ。JSON や説明を付けない。

## 制御タグ

原文にはゲームエンジンのタグが埋まっている。**数・順序・内容を完全に保持する。**

| 形 | 例 | 意味 |
|---|---|---|
| `{g\|...}...{/g}` | `{g\|Encyclopedia:DC}DC{/g}` | 百科事典リンク。**タグ間のテキストは訳す** |
| `{d\|...}...{/d}` | | 同上系 |
| `{n}...{/n}` / `{br}` | | 改行・段落 |
| `{name}` | | プレイヤー名の差し込み |
| `{mf\|男性形\|女性形}` | `{mf\|息子\|娘}` | 主人公の性別で分岐。**必ず男性形が先** |

英語では性別で語形が分かれる箇所でも、日本語は一人称や性別を示す語を省いても自然に読めることが
多い。その結果として作り分けが不要になった場合は `{mf}` ごと省いてよい（例：主語ごと省略する／「彼」「彼女」を
「あいつ」にする）。**性別中立な訳を目指すこと自体が目的ではない**——あくまで
自然な日本語を優先した結果として不要になるだけで、作り分けた方が自然な場合は無理に消さない。
残す場合は男性形・女性形の2つを必ず両方とも保持する。

判定に使う正規表現は [verify.js:72](../verify.js#L72) が正本：

```js
/\{(?:g|d)\|[^}]*\}|\{\/(?:g|d)\}|\{n\}|\{\/n\}|\{br\}|\{name\}/g
```

翻訳時は [toBatchData.js](../toBatchData.js) の `protectControlTags()` で `<ctrl_0/>` 形式の
プレースホルダに退避し、`import` 時に `restoreControlTags()` で復元する方式を取っている
（`extract` が書き出すチャンクの `text` は退避済み、`controlTags` がその対応表）。
Claude Code で直接訳す場合も、**同じ「タグは触らない・間のテキストは訳す」ルールを守る**。

## 参照データの形式

`dev/res/glossary.json` は `{ glossary: [{ source, target, note }] }`。
`dev/res/speakerProfiles.json` は
`{ globalRules: [...], characters: { <名前>: { gender, personality, speechStyle, notes } }, speakerAliases: {...} }`。

## 機械的に直せる control-tag 不整合パターン（2026-09-02 調査）

`node toBatchData.js extract --filter=issues` で拾える control-tag 不整合は、実際には
**大半が翻訳し直す必要のない、機械的なタグの復元で直るもの**だった。1件ずつ手で見る前に
必ず以下の自己検証つきスクリプトを通すこと（`missing`/`extra` が完全に0になった場合だけ
`zhCN.json` に書き戻す。1つでも解決しなければそのキーは一切変更せず手動レビューに回す）。

1. **`{n}...{/n}` の全文丸ごと欠落**（最多。4562件中2040件）: 原文が `{n}` で始まり
   `{/n}` で終わる単純な1ペアで、訳文にその2つが1つも無い場合、既存の訳文をそのまま
   `{n}` + 訳文 + `{/n}` で挟むだけで直る。翻訳し直す必要は無い。
2. **`{g|X}`/`{d|X}` の引数違い（1missing+1extra）**: 正しい位置に用語リンクタグは
   あるが `Encyclopedia:Penalty` のような汎用キーを使ってしまっていて、原文が要求する
   より具体的なキー（`Encyclopedia:Armor_Check_Penalty` 等）と食い違っているだけのケース。
   表示テキストはそのまま、タグの引数だけ原文の値に置き換えれば直る。
3. **完全に余分な `{g|X}...{/g}` ペア（0missing+Nextra）**: 原文に存在しないリンクを
   訳文側が誤って付けているケース。タグだけ剥がして中のテキストは残せば直る。
4. **辞書ベースの欠落ペア挿入**: 上記でも直らない「missing のみ」複数ペアの一部は、
   コーパス全体で `(tagType, argKey) -> 定訳の日本語文字列` を多数決で学習し、その語が
   訳文中に一度だけ（かつ既存タグの外側で）出現する場合に限ってタグで囲むと安全に直る。
   スクリプトは `Z:\Temp\...\scratchpad\autofix_*.mjs`（セッション使い捨てだが、次回また
   `dev/` 直下に similar なスクリプトを書けばよい）。

上記を先に流してから `extract --filter=issues` をやり直すと、残るのは本当に文脈判断が
要る（タグをどこに挿入するか、文章のどこが欠落しているか）少数のキーだけになる。
mf issue も直すなら、上の `verify.js` 修正を先に当ててから抽出すること。
